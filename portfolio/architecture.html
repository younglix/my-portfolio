Data Layer

Database Design

I design schemas around data integrity first, then performance.

users
- id (PK)
- email (unique, indexed)
- password_hash
- created_at

orders
- id (PK)
- user_id (FK, indexed)
- status
- total_amount
- created_at

Indexing, constraints, and migrations are treated as first-class citizens.

Operations

Scalability & Reliability

Stateless Services

No server-side session state, so any instance can handle any request.

Connection Pooling

Database connections are pooled to keep latency low under load.

Caching (Redis)

Frequently accessed data is cached to reduce database pressure.

Background Jobs

Long-running work is offloaded to Celery / worker queues.

Observability

Structured logging and monitoring across every service.
